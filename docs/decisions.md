# Decisions

Short record of what was decided and why. Add a row when a decision changes; do not delete old ones, mark them superseded.

| Date | Decision | Why | Alternatives rejected |
|---|---|---|---|
| 2026-10-12 | Read-only tracking and suggestions first; input automation maybe later, as a separate opt-in spec | Passive capture has the same risk profile as existing community overlays; automation is botting and risks bans | Building automation first |
| 2026-10-12 | Own Npcap capture + own decoder | Independence from a third-party app's undocumented API; can follow every client at once | Consuming a third-party app's local API at runtime |
| 2026-10-12 | Every protocol field is tied to a deliberate in-game action recorded in `captures/`, or to consistency across recordings; no third-party app is a dependency of the app or of the decoder | Anyone with the game and Npcap can reproduce a finding; the app runs standalone | Reusing another tool's decoded stream or opcode table |
| 2026-10-12 | Rust + Tauri 2 core, Angular frontend | Rust is right for capture/decoding; Angular is the frontend convention in use | Python core; .NET |
| 2026-10-12 | Load `wpcap.dll` at runtime (`libloading`), not the `pcap` crate | End users have the Npcap runtime but not the SDK import library the crate links against at build time | Shipping/requiring the SDK; `pcap` crate |
| 2026-10-12 | Captures are classic `.pcap` (Ethernet, µs) | Trivial to read/write ourselves, opens in Wireshark, makes analysis offline and testable without Npcap | pcapng; custom format |
| 2026-10-12 | Filter by BPF `tcp port 13328` instead of discovering endpoints with `GetExtendedTcpTable` | Enough until the port changes | Process-based endpoint discovery |
| 2026-10-12 | Phase 1 crate has no Tauri dependency yet | Tests and the `re` tool build without a frontend; Tauri is added in the Phase 2 plan | Scaffolding the Tauri app first |
| 2026-10-12 | i18n from day one (English first); Rust emits ids/raw values only | Avoids retrofitting; keeps the core free of display text | Hardcoded English strings |
| 2026-10-12 | Do not decode client → server | It is encrypted after an RSA handshake and all game state arrives server → client | Recovering the session key |
| 2026-10-12 | MIT license | Permissive and simple | Other licenses |
| 2026-10-12 | Lax packet parsing not adopted yet | The LSO-truncation claim was unverified; the gap warning in `re dump` will show if frames are being dropped | Switching `SlicedPacket` to `LaxSlicedPacket` speculatively |
| 2026-10-12 | Own LZ4 block decoder in `decode.rs` | The block format is fixed and ~40 lines with bounds checks and synthetic tests; a crate would be a 7th production dependency for the same job. Reconsider only if the game moves to another codec | `lz4_flex` |
| 2026-10-12 | Opcode table embedded (`opcodes.json`, one `default` build label), loaded through `serde_json::Value` | No second build exists to compare yet; the table keeps wire-order hex and is selected by build label so a patch is a data change | External file and build detection before a patch shows what changes |
| 2026-10-12 | `0b 61` is segmented as a whole frame (record count + ascending ids + minimal unfamiliar shapes) | Record bodies are 1 to 17 bytes and not self-describing; a streaming parse cannot tell where a body ends. Every first snapshot tiled exactly | Per-record kind guessing; hard-coding body lengths per counter id |
| 2026-10-12 | **Superseded on 2026-10-16:** `24 e3` is not decoded in Phase 1b | ~60-byte entries with unexplained sub-lists; the checklist counters arrive in `0b 61`/`0c 61` | Parsing the first entry only |
| 2026-10-12 | Phase 2 is split: 2a headless live engine (`state.rs`, `live.rs`, `re live`), 2b Tauri + Angular + `gamedata.json` | The engine can be proven on replays and a live run without a UI; the app then only renders a snapshot plus update events | One Phase 2 plan; app first on recorded data |
| 2026-10-12 | Character state is keyed by `(server, name)`, with one session per client TCP port; a swap on a connection rebinds it | The same name can exist on two servers; one machine can run several clients | Name only; keying by connection |
| 2026-10-12 | `56 36` and the `0b 61` snapshot are held until the next `33 36` and attributed to it; `0c 61` applies at once when the connection is bound | The identity **trails** the world-entry bundle (see `docs/protocol.md`); binding first filed a swapped-in character's bundle under the previous one. Cost: power and snapshot are shown only after the identity | Drop events before an identity; bind on identity and apply later events |
| 2026-10-12 | State is hand-built JSON (`{"version":1,...}`), written to `<path>.tmp`, synced, then renamed; saved at most every 5 s while dirty | No serde derive dependency; a kill never leaves a half-written file; a failed save retries on the next interval | serde derive; a write on every event |
| 2026-10-12 | **Superseded on 2026-10-13:** Closed connections are only unbound in the state (SYN/FIN/RST), not evicted from `Decoder` | A few bytes per connection; evict if long live runs show growth | Evicting streams and framers on FIN/RST |
| 2026-10-12 | **Superseded on 2026-10-16:** Pets are not part of the 2a state | The spec's `Character` has none and pets get their own spec | Folding the pet replay into `state.rs` |
| 2026-10-13 | Keep character bindings after FIN; clear them before decoding a first or changed SYN, and after decoding RST. Track SYN sequence numbers per endpoint direction so retransmitted SYNs preserve the binding | FIN can arrive before missing server data or only half-close the connection; repeated SYNs must not interrupt tracking. Sequence-aware eviction remains deferred if long runs show growth | Clearing the binding on every SYN/FIN/RST |
| 2026-10-13 | A root `Taskfile.yml` wraps the cargo and `uv` commands (`task check`, `task live`, `task re -- <args>`) | One memorable entry point that works from any directory and removes the `--manifest-path` boilerplate; Task is a dev tool, not a crate dependency | Documenting raw cargo commands only; a PowerShell or Makefile wrapper |
| 2026-10-13 | Phase 2b app is a second bin (`acompanion`, `src/main.rs`) in the same crate; one capture thread owns the `Engine` and calls `live::run`; the window talks to it through `characters`, `capture_status` and `restart_as_admin` plus the `characters://update` and `capture://status` events | Reuses the 2a engine unchanged; the window only renders a snapshot and deltas. Testable glue (status ids, error classification, the UAC script) lives in `app.rs`, which has unit tests, while `main.rs` stays thin | A separate crate or workspace; the frontend polling the state file; capture in the Tauri main thread |
| 2026-10-13 | Phase 2b spec gap: `live::run` takes `on_start: impl FnOnce()`, called once the adapter is open (`re live` passes `\|\| {}`) | Without it nothing can report `running`, and the app would only know capture failed or not yet | Reporting `running` optimistically at spawn; polling the thread |
| 2026-10-13 | Phase 2b spec gap: failures are told apart by two typed context markers, `npcap::NotInstalled` and `live::NoAdapter`, found with `anyhow::Error::downcast_ref` (works through added context); elevation is asked with `npcap::is_elevated`, never parsed from a message. `Display` keeps the old texts, so `re` output is unchanged | The spec said "told apart by their error chain"; downcasting is the structured form of that and survives message edits. Missing Npcap or adapter is not fixed by elevating, so those win over `not_admin` | Matching substrings of the error text |
| 2026-10-13 | Phase 2b spec gap: `gamedata.json` carries `weekly_reset_day` (UTC weekday, 0 = Sunday) and an optional per-counter `"ms": true` (value and cap are milliseconds) | Spec §4.3 needs the weekly day. The wire's own `ms` flag is false on every `0c 61` update, so display of a time counter cannot rely on it; gamedata decides | Trusting the wire flag; hard-coding the weekday |
| 2026-10-13 | Phase 2b spec gap: `[[bin]] acompanion` has `test = false` | It has no tests, and a Tauri-linked test harness on Windows can fail to start (`STATUS_ENTRYPOINT_NOT_FOUND`, no Common Controls v6 manifest). The lib and `re` test binaries are unaffected | Embedding a manifest for the test harness; moving the glue to another crate |
| 2026-10-13 | Phase 2b spec gap: CSP keeps `style-src 'self' 'unsafe-inline'`, `dangerousDisableAssetCspModification: ["style-src"]` stops Tauri from rewriting it with hashes, and Angular's `inlineCritical` is `false` in the production build | Angular injects component `<style>` tags at runtime, which a hash-only `style-src` blocks; critical-CSS inlining adds an inline `onload` the CSP forbids. Scripts stay `'self'`-only. Not yet confirmed by an interactive run (no console check) | Hash-only `style-src`; a `nonce` setup; inline critical CSS |
| 2026-10-13 | Visual direction: dark game-tool. Tokens bg `#14161b`, panel `#1b1e25`, line `#2a2e37`, text `#e6e6e6`, muted `#8a8f99`, accent amber `#e0a84a`, ok `#6cc070`, bad `#e06c5a`; dense table rows, thin amber meters, system font (`Segoe UI`), no web fonts | Matches the tools the audience already uses and needs no font download | Light theme; card layout |
| 2026-10-13 | Game data comes from a hand-curated `public/gamedata.json`, compiled once from public sources (game facts only, no account data). A time counter's cap is in seconds at the source; the wire is ms, so gamedata stores ms with `"ms": true`. Only counters matched by id with confidence are included | Names, caps and cycles are not on the wire. The compilation was a one-off dev-time step; nothing is fetched at runtime | Fetching at runtime; guessing cycles for unmatched ids |
| 2026-10-13 | Refills are counted from the 07:00 UTC clock, not from the time of the last update: a boundary is `07:00 UTC + k * every_ms`. `gamedata.ts` carries a `ponytail:` (fixed hour; use the game's next reset once decoded) | Evidence from the compiled game data: for counters 1, 4 and 8 the next refill equals the next daily reset (+N a day at each reset); Odyle Energy (`60000001`) next refill fell on 07:00 UTC + k * 3 h; ids 3 and 101 become full exactly at the next reset (plain weekly resets). Daily reset hour 07:00 UTC and weekly reset Wednesday (`weekly_reset_day: 3`) confirmed from the next daily and weekly reset times. Counting from the update time was off by up to one period | Counting periods from the update time; decoding the wire's "ms to next refill" |
| 2026-10-13 | Curated caps assume the premium membership (Shugo Festival keys 21, Odyle Energy 840; without it the game shows 12 and 560) | No wire field tells which applies, so the dashboard cannot switch. Revisit if a membership flag is found | Showing both; omitting the affected counters |
| 2026-10-15 | Six more counters curated, all `0b 61`/`0c 61` ids already decoded: `60000002` Transcendent rewards (+1 / 12 h, cap 14), `60000006` Conquest rewards (+1 / 8 h, cap 21), weekly `60000007` and `60000008` boss kills (35, 28), `60000009` and `60000010` unclaimed cubes (10, 7). Left out: the per-dungeon Conquest/Exploration families (`600xx101`..`600x9201`, ~16 chips per row), Deus/Arkanis `60005301`/`60006301`, Arena/Battlefield `90000xxx` and `7` | Cycles and periods were compiled once from game data snapshots taken away from the weekly-reset eve (on that day daily and weekly resets coincide and cannot be told apart): a counter's next refill equals the next daily or weekly reset, and the time to full over `cap − left` gives the period. 12 h and 8 h land on the 07:00 UTC clock `gamedata.ts` already uses, so no code change | Curating every id (a row of 20+ chips); guessing cycles for ids never seen off the reset eve |
| 2026-10-15 | The membership expiry is not on the recorded wire, so caps keep assuming premium and no `member_cap` field is added | Exact scans of `login2` and `charswap` found no seconds/ms/µs/FILETIME value, no UTC-offset variant and no start-plus-N-days form (`docs/protocol.md`, "Not yet known"). Adding a switch with no source would be dead code | Building `member_cap` and a `member_until_s` state field now |
| 2026-10-13 | Frontend dependencies: `@tauri-apps/api` (invoke/listen), dev `@tauri-apps/cli` (`pnpm tauri dev\|build`), `@angular/localize` (i18n), plus what `ng new` scaffolds. No direct `serde`: payloads are `serde_json::Value` | Smallest set that gives a window, IPC and translatable strings; the Phase 1 row ("no Tauri dependency yet") anticipated this | A custom webview shell; Electron |

| 2026-10-16 | The pets radar shows the monsters in view and the player's **last exact position with its age**, never an inferred one. Monsters come from `41 36`/`1a 37`/`1b 37`/`1c 37`/`3c 37`/`42 36`; the player's fixes are the zone load (`23 36`) and own-entity skill frames and moves. The map's region is the one most of the pet monsters in view spawn in, kept while none is in view, and the player marker shows only while monsters in view agree with the shown region | Client → server movement is encrypted, so a continuous player position is not on the wire; a position inferred from what is in view is a guess, and a marker that jumps around on a guess is worse than an honest "12 s ago". | 2026-10-19 | Combat: `04 38` is a direct hit and `05 38` a tick (damage or heal over time), `[varint target]` first and the attacker after; `amount` is a varint. Layouts in `docs/protocol.md` ("Combat") | The local player's attacks in `duty-2`, `duty-3` and `login` decode as `04 38` with the attacker equal to the identity's entity and a varying amount; 117 + 28 isolated single hits in `duty-2` are one `04 38` each with no other damage close by | Other `38`-family opcodes (none carries damage); counting the multi-hit list after the amount as extra damage (the recordings give no sign that it is extra damage) |
| 2026-10-19 | A critical hit is bit 0 of the byte after the `04 38` serial (`02` normal, `03` crit); ticks carry no crit (`Hit.crit` is `None`), and the crit rate is critical hits over **direct** hits | Found by correlating single hits with changes in a per-skill crit count; the byte is `02` or `03` in every damage `04 38` of four captures and no other bit between the flags and the trailer separated the hits as it does (159 crit, 217 not). | 2026-10-19 | **Partly superseded on 2026-10-22** (a boss gets its own fight): A fight closes 10 s (capture clock) after its last counted hit or on a new connection; `meter.json` keeps the last 50 finished fights | The spec's fixed gap and cap (`ponytail:`); the capture's `ts_us` as the clock makes replays deterministic | Per-boss fight logic (deferred until the fixed gap misfires) |
